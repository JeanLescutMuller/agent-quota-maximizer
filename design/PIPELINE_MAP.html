2

Predict built

How much of the 5-hour meter will the user still burn before the window resets?

Exactly what is predicted

QuestionAnswerWhy that choice
Which valuepredicted_p95_human_usage_pctThe one number budget subtracts from the window.
Unit% of the 5-hour meter, 0–100The limit is enforced in percent. Units and dollars are display only.
Whose usagehuman onlyIncluding bot spend would predict our own spend as demand and block it.
Which statistic95th percentile, not the averageUnder-predicting blocks the user. Over-predicting only leaves quota unspent, which the next tick can still recover.
Horizonpredicted_horizon_minutes = min(minutes to window_end_ts, 120)"40% over 34 min" and "40% over 120 min" are different claims. 120 = FORECAST_HOURS × 60, how long a measured pace is trusted.
Which windowthe running one only, named by window_end_tsThe backwards fill leaves every earlier window to the user anyway; later windows use MIN_HUMAN_RESERVE_PCT. Budget refuses a forecast whose window has since reset.
Freshnessevery tick; older than 600 s = refusedA stale forecast can miss a user who just started.
If unreadable100Fail safe: a full reserve, nothing is spent.

How today's engine (recent-rate-v1) gets there

rate = max( last_30_min.human_avg_burn_rate 0.40 , current_window.human_avg_burn_rate 0.13 ) # % per minute (raised to ACTIVE_HUMAN_BURN_RATE 0.15 if was_human_active but the meter has not moved yet) predicted_p95_human_usage_pct = rate × predicted_horizon_minutes × SAFETY_MULTIPLIER = 0.40 × 62 × 1.5 = 37 (clamped to 100)

The engine is swappable. Budget reads only three fields (predicted_p95_human_usage_pct, predicted_horizon_minutes, window_end_ts); everything else sits under internals, and a test checks that blanking it changes nothing.

Known gaps

Horizon ignored by budget. With 240 minutes left in the window, the forecast covers only 120 (predicted_horizon_minutes), but budget uses predicted_p95_human_usage_pct as the reserve for the whole window. The last two hours have no forecast, so the reserve is too small.
Budget fills past the guard. Budget fills a window up to 90% (MIN_HUMAN_RESERVE_PCT 10), but execute stops workers above 85% (GUARD_PCT 15). The last 5 points of every full window cannot be spent.
BOT_BURN_UNITS_PER_HOUR is a guess (1.0). It sets max_spend_units_by_time and the lead time. If it is too high, the bot underspends; it never collides. P4 measures it.
